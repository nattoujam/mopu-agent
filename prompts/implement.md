把握で決めた方針で変更を書き、コミットする。

- **論理的なまとまりごとに git commit まで行う**。コミット用の user.name / user.email は設定済みなので変更しない。
- `git add` には変更したファイルを名指しで渡す。`git add -A` や `git add .` は使わない。sandbox が作業ディレクトリに置く書き込み禁止の placeholder（`.bashrc` などが `/dev/null` に見えるもの）を拾って失敗したり、意図しないファイルをコミットしたりするため。
- 与えられたタスクの範囲を超える変更（無関係なリファクタリング、依存の更新、設定ファイルの書き換え）は行わない。タスクを満たすのに要る依存の追加や設定の変更は範囲内。
- 対象リポジトリの指示に、PR を出す前に回すテストやリンタが書かれていれば、それに従って実行する。テストの規約は対象リポジトリの CI なので、指示に無いテストを探して回す必要は無い。
- 実行できずに諦めた操作が完了条件の検証に必要だったなら、**その検証を自分で代替しない**。生成物を手書きで再現したり、目視で「通るはず」と判断したりせず、公開フェーズの PR 本文の「確認してほしい点」に書く。

終わったら、出口ファイルに次のどちらかを書く。どちらの場合も、作業ツリーに未コミットの変更を残さない。

| decision | いつ | 書く項目 |
|---|---|---|
| `done` | 変更をコミットし終えた。次は mopu-agent が push して検証する | — |
| `ask` | 実装の途中で、推測で進められないことが出てきた。それまでのコミットは push され、PR は draft のまま残る | `question` |

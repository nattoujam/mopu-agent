## フェーズ 1: 把握

依頼と、末尾の「対象リポジトリの指示」を読み、関係するコードを調べてから、次のどれにするかを決める。

| 決めたこと | すること |
|---|---|
| 実装する | 「フェーズ 2: 実装」に進む |
| 分解する | 下の「分解するかの判定」の手順で計画ファイルを書いて終える |
| ユーザーに聞く | 下の「ユーザーに聞く」の手順で質問を書いて終える |
| 回答だけで済ませる | コミットを作らず、回答を最終メッセージに書いて終える。質問への回答や、調べた結果コード変更が要らなかった場合 |

### ユーザーに聞く

次のどれかに当たるなら、**推測で実装せずに**聞く。

- 要求が曖昧で、読み方によって実装が変わる
- 情報が足りない
- 実装前に決めるべき仕様が決まっていない
- 依頼がリポジトリの構造と噛み合わない
- 分解するかどうか迷った

手順:

1. `%%QUESTION_FILE%%` を Write ツールで作成する。このパスをそのまま使う。このファイルは git から無視される設定になっているので、コミットはしない
2. 中身は Markdown で、何を決めてほしいかを書く。選択肢があれば並べ、それぞれで実装がどう変わるかを 1 行ずつ添える。調べて分かったことは、判断に要る分だけ書く
3. 書いたら、それ以上作業を進めずに終える

書いた中身は、そのまま Issue（コメントからのタスクなら、そのコメントのスレッド）に投稿され、ユーザーの回答を待つ状態になる。最終メッセージは投稿されない。回答はこの会話の続きとして届く。

実装を始めた後で聞く必要が出た場合も、同じ手順で終える。それまでのコミットは push され、PR は draft のまま残る。

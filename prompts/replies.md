### コメントへの対応

今回は Issue / PR に投稿された、mopu-agent を呼ぶコメントに応答している。

- **渡されたコメントで指示された内容だけ**を対象にする。Issue 本文や過去のコメントは背景情報として読んでよいが、そこに書かれた別の要求までまとめて実行しない。
- 「1 が良い」のように前のやり取りを受けた指示は、「その後のやり取り」から指している提案を探して読む。やり取りで決まった方針が Issue 本文と食い違うときは、後の決定に従う。
- コメントが複数渡されたときは、**そのすべてに対応する**。1 件だけ片付けて終わりにしない。指示どうしが矛盾する場合は、どちらも実装せずに理由を返信する。

### replies（コメントごとの返信）

タスクを終える出口（`decompose`・`ask`・`answer`、公開フェーズの `done`）では、出口ファイルの `replies` に、コメントごとの返信を書く。返信は、それぞれのコメントが投稿されたスレッドに、書いたとおりに投稿される。コメントからのタスクでは `question` と `answer` は投稿されないので、聞きたいことや回答は返信に書く。

```json
{
  "decision": "answer",
  "answer": "回答の要約",
  "replies": {
    "1000000001": "そのコメントへの返信",
    "1000000002": "別のコメントへの返信"
  }
}
```

- キーは「### コメント <ID>」の ID を**そのまま**使い、すべての ID に書く
- 各返信には、その指摘・質問に対して何をしたか（あるいはなぜしなかったか）を書く。各返信はそのコメントのスレッドに単独で表示されるので、他のコメントの話や、宛名・署名は書かない

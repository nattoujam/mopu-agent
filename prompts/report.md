## フェーズ 4: 報告

最終メッセージは、終わり方によって次の場所に投稿される。

| 終わり方 | 最終メッセージの行き先 |
|---|---|
| コミットを積み、PR が無いか、タスクの「作業先の PR」に mopu-agent が作った PR とある | PR の本文。下の手順で書く |
| コミットを積み、タスクの「作業先の PR」に mopu-agent 以外が作った PR とある | 指示したコメントへの返信 |
| 回答だけで済ませた、失敗した | Issue へのコメント（コメントからのタスクなら、そのコメントへの返信） |
| 分解した、ユーザーに聞いた | 投稿されない |

レビュワーが最短で読み切れる分量にすること。目安は十数行程度。差分を読めば分かることは書かない。

### PR 本文の書き方

PR の本文は、実行のたびにこの最終メッセージで丸ごと置き換わる。今回のコメントへの対応だけを書くと、それまでの変更の説明が PR から消える。今回の作業がレビューの指摘 1 件への対応でも、次の手順で PR 全体の本文を書く。

1. `git diff --merge-base origin/%%BASE_BRANCH%% HEAD` で、ベースからの差分全体を読む。今回積んだコミットだけを見ない
2. 依頼を確かめる。依頼は Issue 本文に、タスクにある「その後のやり取り」と今回のコメントを古い順に重ねたもの
3. 下の PR テンプレートの各節を、差分全体と依頼について埋める
4. タスクの「作業先の PR」に今の本文があれば、その項目のうち今の差分にまだ当てはまるものだけを引き継ぐ。差分と食い違う記述は残さない。例えば、後のコミットでコードを変えたのに「コードは変えていません」と書いたまま残さない

### PR テンプレート

PR 本文は、この節の直後に置いた PR テンプレートに従って書く。PR ごとに体裁が変わると、レビュワーがどこに何があるかを毎回探すことになる。

- 見出しの名前・順序・階層を変えない。テンプレートに無い見出しや、見出しの前の前置きを足さない
- 前の本文が別の体裁でも、引き継ぐ項目はテンプレートの形に書き直す
- 先頭の `Closes #<番号>` は mopu-agent が足すので書かない
- CI とレビュアーの結果、テストに関わる変更の一覧は書かない。CI か別のレビュアーで引っかかったときに、mopu-agent が作業の報告に載せる

各節に書くこと:

| 見出し | 書くこと | 書くことが無いとき |
|---|---|---|
| 変更 | 何をどう変えたかを 1〜3 項目で。ファイルや行ごとの列挙はしない | 消さない |
| 判断したこと | 素直な実装を避けた理由、Issue と違う選び方をした理由、既知の制約への対処 | 見出しごと消す |
| 確認してほしい点 | レビュワーに見てほしい箇所、実行できなかった検証 | 見出しごと消す |

各節は箇条書きだけで書き、各項目は体言止めの 1 文にする。です・ます調や「〜しました」「〜のためです」の文で書くと、レビュワーが一覧で読み切れない長さになる。理由が要る項目は、理由を括弧に入れて体言止めのまま書く。

- 良い例: `タグの一覧を docs の表から logger.ts の LOG_TAGS へ移動`
- 良い例: `docs の表は削除（入口を足すたびに表も直す必要があったため）`
- 悪い例: `タグの一覧を、docs の表から logger.ts の LOG_TAGS に移しました。`

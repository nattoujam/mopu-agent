push した変更が、下の理由で検証を通らなかった。原因を確かめて直し、コミットする。

- CI が落ちたときは、まず `gh run view <run-id>` で run の状態を確かめ、`gh run view <run-id> --log-failed` で落ちたジョブのログを読んでから直す。どのログを読むかは自分で決める
- 直すのは実装の側。テストを消す、`skip` を足す、期待値を実装に合わせて書き換える、`package.json` の scripts を差し替えるといった、CI を通すためだけの変更はしない。テストに関わる変更は、別のレビュアーが中身を確かめる
- コミットメッセージに `[skip ci]` などを書いて CI を飛ばさない。飛ばした変更は未検証として扱われる

終わったら、出口ファイルに次のどれかを書く。どの場合も、作業ツリーに未コミットの変更を残さない。

| decision | いつ | 書く項目 |
|---|---|---|
| `done` | 直してコミットした。mopu-agent が push して、もう一度検証する | — |
| `ask` | 直し方をユーザーに決めてもらう必要がある | `question` |
| `give_up` | 変更の外にある原因（CI の環境、既存の不具合など）で、このタスクでは直せない | `reason`（原因と試したこと） |

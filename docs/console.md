# Web コンソール

`poll.sh` を一定間隔で自動実行し、設定とログをブラウザで扱う。

```bash
./console.sh
# → http://127.0.0.1:8787
```

Python 3 の標準ライブラリだけで動く。スケジューラと HTTP サーバを 1 プロセスに持つ。
時間が来ると `poll.sh` を子プロセスで起動し、出力を `logs/console/poll-<日時>.log` に残す。

## 画面

タスクの進み具合を追うのは [Nextcloud Talk への通知](#nextcloud-talk-への通知)に任せ、コンソールは設定と、失敗したときに詳細を掘るのに使う。

左の列には常に次の 3 つが出る。

| 領域 | 内容 |
|---|---|
| 稼働状態 | 次回ポーリングまでのカウントダウン、実行間隔、最終ポーリング時刻、`poll.lock` の保持状況、直近の 5h 枠 |
| スケジュール | 実行間隔の変更（`300` / `5m` / `1h` のいずれの書き方でも可）、一時停止と再開、今すぐ実行 |
| ログの書き出し | ログとコスト実績を tar.gz で保存する。[ログの書き出し](#ログの書き出し)を参照 |

右はタブで切り替える。

| タブ | 内容 |
|---|---|
| タスク | `logs/<owner>__<repo>/<task-id>/` の今の[フェーズ](task-flow.md#フェーズ)・結果・コスト・ターン数と、詳細ではフェーズの移り変わりと時刻、`stream.jsonl` を読み下したイベント列。ツール呼び出しは引数を項目ごとに整形する。各イベントの `raw` ボタンで対応する 1 行だけをモーダルで開けるほか、`stream.jsonl` 全体と `stderr.log` / `setup.log` も原文のまま読める。失敗したタスクには「再実行」ボタンが出る。上の欄に task-id の一部を入れると絞り込み、1 件に絞れた状態で Enter を押すとその詳細を開く |
| ポーリング履歴 | 実行ごとの終了コード・所要時間・検出/処理件数と、ログ本文（実行中のものは 2 秒ごとに追尾する）。連続した「タスクなし」は 1 行に畳まれる |
| 計測 | リポジトリ毎の累計コストと[ループの計測](#ループの計測) |
| 設定 | 対象リポジトリの追加・削除と、リポジトリごとの設定（タスクを受け付けるユーザーなど）、全体の設定（利用枠の閾値など）の編集。保存時に検証し、誤りのある項目を示す。GitHub App と Nextcloud Talk の通知の登録もここで行う |

## Nextcloud Talk への通知

設定タブで登録すると、タスクの進み具合を Nextcloud Talk の会話に bot が投稿する。

用意するもの:

- Nextcloud Talk に登録した bot と、その secret
- bot を有効にした会話の token（会話の URL の `/call/` に続く英数字）

bot の登録と会話での有効化は Nextcloud 側で行う（[Talk の bot のドキュメント](https://nextcloud-talk.readthedocs.io/en/latest/bots/)を参照）。
登録時にテストメッセージを 1 通送り、届かなければ登録しない。secret は `state/secrets/nextcloud.json`（ファイル 600）に置かれ、
画面には出ず、ログの書き出しにも含まれない。

投稿するもの:

| 出来事 | 通知音 |
|---|---|
| タスクの開始（リポジトリ・Issue 番号・タイトル・task-id） | なし |
| 実装に入ったこと（エージェントが書いた実装の方針） | なし |
| 検証に入ったこと（前回の検証から変更したファイル数とコミット、CI の結果） | なし |
| CI の失敗と、レビュアーの差し戻し（理由）、それを受けて実装に戻ったこと | なし |
| 公開（レビュアーが承認したか） | なし |
| レビュー待ち（PR のリンク、最終メッセージの冒頭の段落、推定コスト）・回答済み（回答の冒頭の段落）・回答待ち（質問の冒頭の段落）・承認待ち | あり |
| 失敗（理由と task-id） | あり |
| 分解案の承認による sub issue の作成、親 Issue のクローズ | なし |
| 差し戻しからの学習・棚卸しで出した Issue と、その失敗 | あり |
| 利用枠・レート上限による停止 | あり |
| 利用枠が戻っての再開 | なし |
| ポーリングの中止（設定の誤り、認証切れなど）と、その復旧 | 中止はあり、復旧はなし |

- タスクは `リポジトリ名#Issue 番号` の形で示す（owner は省く）。同じタスクの通知も返信やスレッドにはまとまらず、1 通ずつ並ぶ
- 通知音が鳴るものは、状態を太字にしてタスクのタイトルも載せる。Talk が Markdown として描画する
- 停止とポーリングの中止は、状態が変わったときだけ投稿する。直らないまま毎回の実行で同じ理由で止まっても、2 通目は出ない
- 「処理するタスクはありません」と、進行中 PR があるためのスキップは投稿しない
- push していない・CI が実行中といった理由でエージェントを待たせたことは投稿しない。ツール呼び出しの 1 つ 1 つは、タスクタブで見る
- 失敗の通知にはコンソールへのリンクを載せない。task-id をタスクタブの欄に貼ると詳細を開ける
- 送れなかったときは、ポーリングのログに警告が出る。タスクは止まらない

## ポーリング履歴の畳み込み

何も処理しなかった実行（終了コード 0、処理 0 件、警告もエラーもなし。検出はしたが
sub-issue 未マージや進行中 PR 過多でスキップしただけの実行も含む）が連続したぶんは、
`タスクなし ×13 20:49 〜 21:44` のような 1 行にまとまる。行をクリックすると個別の実行に展開する。

短い間隔で回しているとタスクを処理した実行が埋もれるため。5 分間隔なら 1 時間で 12 実行増える。

## ループの計測

計測タブのリポジトリ毎の箱に、エージェントの PR がどれだけ差し戻されたかを出す。ポーリングのたびに更新される。

| 表示 | 内容 |
|---|---|
| 差し戻し PR | マージされたエージェントの PR のうち、PR ができた後に `/claude` のコメントで作業させたものの数 |
| PR あたり | マージされた PR 1 本あたりのコスト。差し戻しや分解の提案など、同じ Issue の実行をすべて含む |
| 拒否 | sandbox や権限の設定でエージェントのコマンドが拒否された回数 |
| 種類ごとの件数 | 差し戻しのコメントを「設計・仕様の判断」「見た目」「検証の実行」「書式」「その他」に分けた件数 |

差し戻しの種類は、コメントの本文を LLM で分類する。差し戻し 1 件につき 1 回分類し、その分だけ利用枠を使う。

コメントの本文を控えていない古いタスクは「未分類」になる。`state/followup-categories.jsonl` に
`{"task": "<task-id>", "category": "<種類>"}` の行を足せば、その分類が使われる。

## ログの書き出し

「7 日」「30 日」「全部」のボタンで、その期間に始まったタスクとポーリングのログを `mopu-dump-<日時>-<コミット>.tar.gz` として保存する。
`GET /api/dump?days=<日数>` でも取れる（`0` は全部）。

| 含むもの | 含まないもの |
|---|---|
| `logs/<owner>__<repo>/<task-id>/`、`logs/console/`、`state/` の設定・コスト実績・計測・リポジトリごとの状態 | `state/secrets/`（GitHub App の鍵）、`state/askpass.sh`、作業ツリー、clone したリポジトリ |

GitHub と Anthropic のトークン、秘密鍵の形をした文字列は `***` に置き換える。置き換えた件数と、書き出した時点の
mopu-agent のコミットは、アーカイブの `dump.json` に入る。

## 失敗したタスクの再実行

タスクタブの詳細で「再実行」を押すと、`./poll.sh --repo <owner/repo> --retry <番号>` が走る。前回の作業ツリーを
そのまま引き継ぐので、途中まで進んだ変更を捨てずに続きから再開できる。

ボタンが出るのは `失敗` / `中止` / `未完了` のタスクだけ。成功したタスクは作業ツリーが
消えているため、`--retry` しても引き継ぐものがなく、ただの再実行になる。

`中止` は、エージェントを起動する前に打ち切られたタスク（依存の準備の失敗、worktree の
準備の失敗）。`stream.jsonl` が作られていないので、原因は `setup.log` 側に出る。

## 設定

エージェントの設定は画面の「設定」タブで変更し、`state/settings.json` に保存される。
項目と既定値、入力の制約は `settings/schema.json` にある。`poll.sh` は起動時に 1 回だけ読むので、
保存した変更は次回のポーリングから効く。

- 設定が 1 度も保存されていないと、`poll.sh` は起動を拒否し、画面は「設定」タブを開いた状態で始まる
- リポジトリ名は登録後に変えられない。別のリポジトリにするときは追加して、古い方を設定から外す
- 設定から外しても、`state/repos/` の記録やログ、作業ツリーは消えない。同じリポジトリを追加し直すと引き継がれる
- 新しく追加したリポジトリは、`./setup.sh --repo <owner/repo>` でラベルを作るまで poll が拒否する
- ラベル名は `agent:queued` などに固定で、変更できない

コンソール自体の待受先は、起動前に要るので `config.env` で指定する（すべて任意）。

| 変数 | 既定値 | 説明 |
|---|---|---|
| `CONSOLE_HOST` | `127.0.0.1` | 待受アドレス |
| `CONSOLE_PORT` | `8787` | 待受ポート |

間隔と一時停止の状態も、画面で変更した時点で `state/settings.json` に保存される。再起動後も引き継がれる。
初めて起動したときは 5 分間隔の一時停止状態で始まる。

間隔は 60 秒〜24 時間。起動直後は実行せず、必ず 1 間隔ぶん待つ。起動しただけで利用枠を削らないため。
すぐ走らせるには「今すぐ実行」を押す。一時停止中でも動く。

## 常駐させる

systemd user service にすると、ログイン中は回り続ける。

```ini
# ~/.config/systemd/user/mopu-console.service
[Unit]
Description=mopu-agent web console

[Service]
ExecStart=%h/Code/mopu-agent/console.sh
Restart=on-failure

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable --now mopu-console
journalctl --user -u mopu-console -f
```

停止時（`SIGTERM` / `Ctrl-C`）は、実行中の `poll.sh` を最大 5 分待ってから落ちる。
途中で殺すと `agent:running` ラベルが Issue に残るため。

## 注意

**コンソールは認証を持たない。** ここから `poll.sh` を起動できる＝ローカルの `claude` を任意に走らせられる。
設定画面の「依存の準備コマンド」は sandbox の外でホストが実行し、「コンテナで回す検証」はホストの docker で
任意のイメージを起動するので、コンソールに触れる人はホスト上で任意のコマンドを実行できる。
そのため loopback 以外での待受は既定で拒否する。公開する場合は `CONSOLE_ALLOW_REMOTE=1` を設定し、
前段のリバースプロキシで必ず認証をかけること。

ブラウザで開いた無関係なページからの操作は受け付けない。`Origin` と `Host` を照合しているので、
前段のプロキシで `Host` を書き換えると画面から操作できなくなる。`Host` はそのまま転送すること。
